# 数据站云端部署方案（长期稳定运行 · 2026-09-08）

> 情景：公司一台电脑 7x24 跑数据站，同事需要远程接入。目标：上云、长期稳定。
> 配套件：`deploy/cloud/`（systemd 单元 + 一键安装 + 每日备份 + Caddyfile）。
> 原则与公司端部署一致：**git 跟踪文件零改动，全部定制在 gitignored 配置里，`git pull` 永久无冲突**。

## 一、路线结论

| | A. 云服务器直跑（**推荐**） | B. 公司电脑 + 隧道 |
|---|---|---|
| 做法 | 香港轻量服务器跑全套（serve+refresh） | Tailscale / Cloudflare Tunnel 暴露公司电脑 8787 |
| 长期稳定 | ✅ systemd 自愈 + 云厂商 SLA，不受公司断电/IT 策略/安全软件影响 | ❌ 公司电脑仍是单点（实际发生过：防火墙规则被安全软件清掉、境外直连被断靠代理续命） |
| 网络 | ✅ 香港节点境外源直连（告别代理），国内财经源大多可达 | 维持现状（境外流量继续依赖 7897 代理） |
| 同事接入 | ✅ 永远连同一个域名 | Tailscale 每人装客户端（免费 3 用户上限）；CF Tunnel 免装但国内访问 CF 边缘质量波动 |
| 成本 | ~¥30-70/月 | ¥0 |
| 迁移量 | 半天 | 零 |

**结论：A 为目标态；B 只在零预算过渡期用。** 数据站核心链路（serve/refresh/translate/store）已审计为零 Windows 绑定，可原样上 Linux；refresh 单实例锁已补 fcntl（Linux 分支）。

## 二、选型

- **节点：香港**。数据面 = 境外源（土耳其 KAP/美股/港股）+ 国内源（新浪/东财/金十/华见）；香港两头都通。选内地节点则境外源又要在云上自建代理，回到老问题。
- **机型**：轻量应用服务器 2 核 2G / 40-60G SSD / 1T+ 月流量（当前库 9MB、内存占用轻，规格够用一两年）。阿里云/腾讯云香港轻量 ~¥30-70/月。
- **系统**：Ubuntu 24.04 LTS。
- **域名**：加一条 A 记录（如 `data.公司域名`），Caddy 自动 HTTPS。无域名可临时 `http://IP:8787`+key（Bearer 明文传输，只宜试用不宜长期）。

## 三、部署步骤（十步）

```bash
# 1. SSH 密钥登录云机, 装基础件
apt update && apt install -y git python3-venv caddy

# 2. 克隆
git clone https://github.com/1375692655hzh/ai-auto-gen.git ~/ai-auto-gen
cd ~/ai-auto-gen

# 3. 一键部署(venv + systemd: serve 常驻自愈 / refresh 每15min / 备份每日04:30)
sudo bash deploy/cloud/install.sh
curl -s http://127.0.0.1:8787/v1/health   # 此时未配 key, loopback 免密 → 应返回 status ok

# 4. 填 3 个 local 配置(全部 gitignored; 从公司电脑抄或按模板新建)
#    a) global-news-sources/config/api_keys.local.json   每同事一把 key(见第五节)
#    b) ai-workflow/generator/config.local.yaml          翻译链(见第四节)
#    c) auto-publisher 兄弟仓的 secret.local.json        LLM 全局 key(拆仓后路径见 AGENTS.md)

# 5. (可选)迁移历史数据: 公司电脑上
#    scp data/serve/items.db user@云机:~/ai-auto-gen/data/serve/   # 翻译缓存随库带走
sudo systemctl restart aag-serve

# 6. 立即刷一轮验证写侧
sudo systemctl start aag-refresh.service
journalctl -u aag-refresh -n 30 --no-pager

# 7. HTTPS 反代
sudo cp deploy/cloud/Caddyfile /etc/caddy/Caddyfile   # 先改域名
sudo systemctl reload caddy

# 8. 防火墙: 只开 22/80/443(8787 不直接暴露)
sudo ufw allow 22,80,443/tcp && sudo ufw enable

# 9. SSH 加固: /etc/ssh/sshd_config 设 PasswordAuthentication no 后 restart sshd

# 10. 端到端验证
curl -H "Authorization: Bearer <某同事key>" https://data.example.com/v1/health
```

## 四、翻译链云端选型

- **简单档（推荐起步）**：DS 官方按量 key 直连（`api.deepseek.com` 香港可达），`config.local.yaml` 链位 1 填 `oc` 之外的 `base_url/api_key/model` 三件套。翻译量小（每天几百条），月成本个位数元。
- **省钱档**：装 Node ≥22 + `npm i -g omniroute` 复刻免费链。注意：香港出口对 muse 是否解锁**未实测**，上线先按 `docs/翻译模型实测与推荐.md` 的口径跑三样本题再定链序。
- Ark（火山 `cn-beijing`）从香港可达性同样需实测。

## 五、同事接入（key 管理）

`api_keys.local.json` 的 `keys[]` 数组**每人一项**：

```json
{"name": "zhangsan", "key": "<64位随机hex>", "enabled": true,
 "rpm": 60, "daily_items": 200000, "daily_snapshot": 10}
```

- name=key 归属（审计可读）；rpm/daily_items 即个人配额，管理员可给大值事实无限。
- 工作台设置页：连接模式=局域网数据站 → 地址 `https://data.example.com` → 粘贴个人 key → 测试连接。
- 直连 API 同样有效：`/v1/items`、`/v1/snapshot/latest`、`/v1/status`。
- 注意：**一旦配置了 key，本机 loopback 访问 `/v1/*` 也要求带 key**（serve 设计如此）。

## 六、长期稳定运行清单

| 项 | 机制 |
|---|---|
| serve 存活 | systemd `Restart=always`，崩溃 5s 自愈 |
| 数据新鲜度 | timer 每 15min + `Persistent=true` 错过补跑 + 单实例锁（撞锁跳过） |
| 轮内预算 | 抓取 12min + LLM 收尾 3min 自钳制（跨平台，防轮次重叠堆积） |
| 日志 | journald 自带轮转；`journalctl -u aag-serve -f` 实时看 |
| 备份 | 每日 04:30 SQLite 在线备份 + 两份 local 配置 → `data/backups/` 保留 7 份 |
| 拨测告警 | UptimeRobot（免费）带 key 打 `/v1/health`，挂了邮件/微信推送 |
| 升级 | `git pull && sudo systemctl restart aag-serve`（local 配置不动，零冲突） |
| 数据面监控 | `GET /v1/status` 看最近一轮战果与 dead 源清单 |
| 磁盘 | 库现 9MB、日志有 journald 上限；每年看一眼 `df -h` 即可 |

## 七、已知 Linux 差异（诚实清单）

- **运维台 8786**：进程/任务计划面板用了 netstat/schtasks（Windows 专属），Linux 上降级显示；云端运维面 = SSH + `systemctl`/`journalctl`。控制台可不开（`deploy/cloud` 未含它的单元）。
- `bin/*.bat` 与 schtasks 注册不适用；systemd 单元替代。
- CLI 层完全一致：`cli.py sources serve/refresh/list/check/enable` 跨平台。

## 八、公司电脑去向

直接退役；或保留 1-2 周只跑 refresh 不对外（灾备观察期），云上稳定后关闭。若保留，其 `config.local.yaml` 的 serve 地址无需改动（工作台同事侧各自改指云端域名）。
