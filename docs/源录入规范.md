# 源录入规范（新信息源接入手册）

> 2026-08-30 制定。配套文档: `add-a-source.md`(接入的代码操作) / `docs/调研/作息-汇总.md`(现有八源作息)。
> 任何时候要加源, 先填「源登记卡」, 再走「七步录入流程」。三问必答: **什么市场 / 给什么 / 何时更新**。
> 在册模型(2026-08-30 用户定): 能跑通的源就在册可用, 不做"禁用"式雪藏; 用不用某源由工作流运行时选取
> (`--set peer_sources=源名,...` / `--set flash_sources=源id,...`)。`enabled` 开关只剩一个含义:
> 缺 key/被封等**跑不通**的源暂不占位, 修好即翻开。

## 一、源登记卡（录入前必填）

```markdown
## 源登记卡: <源名>
- 源名/显示名:            # 如 "CNBC Daily Open美股晨报"
- 提供方:                 # 媒体/机构, 如 CNBC / Anadolu Agency
- 市场覆盖:               # 地理市场限定七个(2026-08-30 用户裁决): A股 / 港股 / 美股 / 日本 / 韩国 / 台湾 / 土耳其
                         # 资产类别源(独立于地理市场, 同日用户许可): 外汇(investingLive; FXStreet被403禁用待恢复) / 大宗(SMM)
                         # 其余范围外(印度/欧洲/拉美/澳新/中东其他/加密)一律不接, 调研时直接落选
- 语言:                   # 中文 / 英文 / 日文 / 韩文 / 土耳其语(synth 支持多语言, 输出始终中文)
- 内容形态:               # 五选(可组合), 见下方映射表
  □ 成篇早报(晨报型: 隔夜回顾+今日展望+关键数字)   □ 快讯流(滚动单条)
  □ 数据行情(指数/汇率/价格快照)                   □ 公告(交易所披露类)
  □ 深度分析/观点
- 更新作息:               # 周几发(周一~日) × 每日时刻(北京时间); 节假日行为; 依据样本天数
                         # 如 "周一~五 09:10 与 14:00-16:06 两版, 周末零发布(15 工作日样本)"
- 当日版可抓时点:          # 北京时间几点后能抓到当日版(排程用)
- 获取方式:               # RSS / JSON API / HTML(SSR) / 需浏览器/登录态
- 反爬等级:               # low(直接抓) / medium(cookie/频控) / high(Cloudflare/登录)
- 质量备注:               # 是否混时政娱乐 / 付费墙 / 正文长度 / 数字密度
```

**快速通道**: 你随手丢来一个 URL 时, 最少先答三问(市场/形态/作息), 其余字段可由 agent 调研补全
(方法论见第五节)。

## 二、内容形态 → 源库映射（决策表）

| 内容形态 | kind | 数据去向 | 现有参照 |
|---|---|---|---|
| 成篇早报 | `peer_article` | `peer_mornings` 聚合 → morning-digest 的 synth 汇总 | 富途/财联社/AA/CNBC |
| 快讯流 | `flash` | `gather` → morning-paper 的 rank 精排 | 新浪7×24/东财快讯 |
| 数据行情 | `market` | `fetch_extras` 版式素材(长图"外围市场"区) | global_markets |
| 公告 | `announcement` | `fetch_extras` 版式素材(公告区) | cls_announcements |
| 深度分析 | `peer_article` 或不接 | 质量高进聚合(供 synth 背景); 观点流不接(防污染事实底稿) | — |

参数速记:
- `ttl_min`(缓存分钟): 滚动快讯 10 / 日更内容 60-120 / 日更早报 120
- `risk`: low 免登录直抓 / medium 带 cookie 或频控 / high 登录态或 WAF(默认不进自动链, 手动取用)
- `default_enabled`: 进聚合消费的 peer 源**不写**(避免与聚合重复抓取, 参照富途/财联社)

## 三、七步录入流程

1. **调研验证**(可派 agent): 拉至少 7 天真实历史条目 → 填满登记卡的作息/反爬/结构; 实测 HTTP 状态与解析点(标题/正文/时间字段在哪)。
2. **定 kind 与接入方式**: 查映射表定 kind; 实现方式按 `add-a-source.md` 三种(纯配置/抓取函数/浏览器态)。
3. **实现抓取函数**: 放 `generator/extra_sources.py`(早报类)或 `generator/sources.py`(快讯类); 统一返回 `{"time": "YYYY-MM-DD HH:MM", "text": ..., "source": 显示名}`, 文章型加 `title/media/url`; 带UA、超时15s、失败抛异常(不吞, 健康机制自动记; "没数据"与"故障"的区分见第六节异常纪律); time 必须换算北京时间(源时区≠北京时要转)。
4. **注册**: `sources/builtin.py` 加 `@source` 薄包装; 早报类同时接进 `fetch_peer_mornings()` 聚合元组(失败降级不炸聚合)。
5. **实测**: `python cli.py sources fetch <id> --fresh` 必须实抓成功; 当日未发布的源, None 属正常但要贴出接口通了的证据。
6. **文档登记**: `add-a-source.md` 源列表追加一行(入口/结构/作息一句话); `docs/调研/作息-*.md` 追加该源作息(或新建)。
7. **排程对齐**: 对照 `作息-汇总.md` 的跑批矩阵——该源"当日版可抓时点"若晚于工作流跑批时刻, 明确标注"仅补班可用"(早班 08:30 / 午后 14:30 / 夜班 23:40), 不要默默接进早班链。

## 四、防坑清单(来自已踩过的坑)

- **旧 RSS 冻结陷阱**: feeds.a.dj.com / mw_marketpulse / investing news_285 等返回 200 但数据停在 2024-2025——**接入前必须验证最新条目时间戳**, 不是 200 就算活。
- **feed 选稿≠网站全量**: 共同社 fzone feed 不含每日收盘稿(只有大涨大跌日)——调研要看 feed 实际给什么, 不是网站有什么。
- **时区三坑**: ①源时区换算北京时间(JST/KST +9、TR +3、UTC 0); ②"当日"过滤按北京日期, 跨时区源的当日定义要对齐; ③土耳其/美股收盘在北京深夜, 当日综述永远赶不上当日早班。
- **周末行为必须单独验证**: 见闻周日全停、BHT 周末停摆、CNBC 周末零发布, 而财联社/AA/韩联社周末照发——周末跑批的源可用性差异极大。
- **URL 发现层是生命线**: Yahoo Morning Brief 文章页能抓但发现层断裂=不可用; 归档页/搜索接口/RSS 至少要有一条稳定发现通道。

## 五、调研方法论(给 agent 派工时直接引用)

- **作息统计**: 拉历史条目(归档页翻页/RSS 窗口/Wayback 快照/项目存档 `data/runs/*/fetch.json` 的 time 字段), ≥7 天样本, 周六周日单独计数, 节假日行为标注。
- **结构验证**: curl 实测(标准 UA 无 cookie), 记录状态码/体积/解析点; 反爬等级以"能否免登录稳定复抓"为准。
- **质量评估**: 是否晨报型(隔夜回顾+展望)而非标题流; 正文长度; 数字密度(LLM 保真基础); 混入时政/娱乐比例。
- 三家分工先例: grok(英文源联网+curl)、gemini(日韩+Wayback 历史重建)、codex(中文+土耳其, 可写临时脚本统计)。

## 六、异常纪律(没数据 ≠ 故障)与限速阈值备查

异常三级约定(移植自 simonlin1212 数据工具包的核心设计, 2026-08-31 用户拍板成文; 48 源此前靠自觉遵守, 此后为强制规范):

1. **没数据 → 安全返回空**: 休刊日/非交易日/当日尚未发布 → 返回 `[]`/`None`, 聚合层记"今日未发布或未命中", 调用方安全跳过。例: nasdaq_earnings 周末零财报、miningcom 周日无更、BHT 周末停摆。
2. **故障 → 必须抛异常冒泡**: 被封(401/403/整站 WAF)/解析结构改版/关键字段缺失 → raise, failed 列表带异常类型与原因。**绝不允许把故障伪装成"没数据"**(如 try 包整个函数体吞成空列表)——否则源死了无人知晓, 早报悄悄缺料。例: nbs_pmi 三个主指标解析不到直接 fail-fast "措辞可能已变更"; wscn_live 校验 `code==20000` 否则抛错。
3. **判断口诀**: 问"这个空结果是源的正常作息, 还是源病了?"——前者返回空, 后者抛错。拿不准就抛错: 误报一次故障, 比漏报一次源死亡便宜得多。

限速阈值备查(东财系, 社区 2026-05 实测): **每秒 >5 次 / 单 IP 并发 ≥10 / 1 分钟 ≥200 次 → 临时封 IP**。东财系接口(push2/datacenter/np-weblist)共用同一风控面, 封一台住宅 IP 成片失联; 备胎源必须跨域名跨风控面(本项目财联社电报 cls.cn 与东财全球 eastmoney.com 互备即此原则)。

- **当前不建限流器**: 早报管线每日 1-2 跑 × 每源 1 页, 离阈值几个数量级(2026-08-31 裁决, YAGNI)。
- **触发线**: 凡新增"批量回刷历史公告/批量抓个股/高频轮询"类功能, 先做同域名限流器(最小间隔+随机抖动+Keep-Alive 会话复用+403 不重试——403 是东财风控信号, 重试反而加重)再上线。
