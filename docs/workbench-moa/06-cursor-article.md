# 图文页四子页页面规划（cursor）

> 取代 `workbench/web/js/pages/article.js` 旧三栏草版。壳层约定对齐资讯页：`article.js` 在 `mounted` 里调 `WB.shell.setSubs([{id,title,icon,cnt,onPick}], activeId)` 注册左侧四子菜单，`unmounted` 清空；四子页用 `v-show` 保状态。路由仍是 `#/article`（`app.js` 只按整段 hash 匹配主页面，子页不改 hash 解析）。
>
> 设计铁律（`app.css` 头注释）：禁 emoji 图标（子菜单用内联 SVG）、单 accent（熔琥珀）、4pt 间距阶梯、数字 `tabular-nums`、面板 10px 圆角、数据列表用 1px 分隔线、禁止卡片套卡片。
>
> 红线：对三板块全程只读；绝不手编 `auto-publisher/autopub/state.json`；发布按钮本期一律留桩，提示走 `python cli.py publish run --draft`；工作台自有可写区仅 `data/workbench/*.json`。

## 一、四个子页面

四个子菜单 id：`reco` / `gen` / `pub` / `auto`。左菜单 `cnt`：推荐信息=当前命中条数；内容生成=草稿数；内容发布=待发草稿数 + 账本 uncertain 数（有待核时才显示）；自动化任务=已启用任务数。计数随接口返回更新，模式同 `news.js` 的 `registerSubs()`。

### 1.1 推荐信息（`reco`）

#### 页面目的

从「选的源」里，按回溯时间窗取出条目，用价值/重要性近似分排序，再用标签筛选收窄，作为内容生成的素材入口。用户在此勾选信息，一键带入【内容生成】的信息选择区。本页不写三板块文件，不触发抓取。

覆盖要素：**选的源**、**回溯时间范围**、**价值/重要性排序**、**标签筛选**。

#### 布局区块

```
+--------+------------------------------------------------------------------+
| 子菜单  | 工具条（单行, 4pt 间距）                                           |
|        |  回溯 [近1小时|近4小时|近24小时|近3天|全部]                           |
| 推荐信息|  排序 [价值分|时间新到旧]                                            |
| 内容生成|  已选源 N  ·  命中 128  ·  [把勾选加入生成]                          |
| 内容发布|------------------------------------------------------------------|
| 自动化  | 标签筛选行（.chip, 与资讯页同一套枚举, 非卡片）                       |
|  任务  |  市场[]  类型(item_type)[]  定位[]  形态[]  情绪[]  [清空]          |
|        |------------------------------------------------------------------|
|        | +----------------+--------------------------------+-------------+ |
|        | | 选的源         | 推荐列表（1px 行, 非卡片）       | 本条构成    | |
|        | | 搜索源 ID/名   |--------------------------------|             | |
|        | | [x] 全选启用源 | 分 | 标题摘要 | 源 | 时间 | 操作 | 价值分 8.5  | |
|        | | [x] reuters    | 8.5| NVDA... | .. | 12:01| 勾选 | 同事件 x3   | |
|        | | [ ] bloomberg  | 6.0| ...     |    |      | 加入 | 官方 +2     | |
|        | | [x] cls        |    |         |    |      |     | 财报 +2     | |
|        | | 常用源 [留桩]  | 底部 [加载更多] 游标              | 标的 x0.5   | |
|        | +----------------+--------------------------------+-------------+ |
+--------+------------------------------------------------------------------+
```

- 左栏「选的源」：来源清单（启用源优先），勾选即过滤；默认全选 `enabled=true` 且非 dead 的源。不套卡片，用 1px 行 + checkbox。
- 中栏推荐列表：行式，数字列 `tabular-nums`。勾选多条后点工具条「把勾选加入生成」。单行「加入」立即带入并跳转。
- 右栏「本条构成」：点中某行后展示 `score_parts`（为什么排在前面）。空态文案：「点一行看价值分构成」。
- 「常用源收藏」本期按钮可见但 disabled，桩文案：「下期：把当前勾选存成常用源组」。

#### 数据来源

| 用途 | 接口 | 标注 |
|---|---|---|
| 源注册表（选的源左栏） | `GET /wb-api/v1/sources` | **现有接口** |
| 源健康/条数（dead 灰掉、按产量排序可选用） | `GET /wb-api/stats` | **现有接口**（60s 缓存） |
| 标签枚举（市场/形态从源聚合；类型/定位/情绪用资讯页封闭枚举） | 同上 + 前端常量（对齐 `news.js` `enums`） | **现有** |
| 推荐排序后的条目流 | `GET /wb-api/recommend?...` | **需新增接口**（见第三节；后端已有 `reco.py` 骨架，本方案按完整契约扩展） |
| 条目原始流（降级：推荐端点不可用时退回按时间） | `GET /wb-api/v1/items?since=&sources=&...` | **现有接口** |

条目本身没有「价值分 / 重要性」字段。本期用服务端近似算法打分，分数随响应返回，UI 可展开构成；真·模型打分字段留桩（响应里预留 `score_model: null`）。

**本期近似算法（服务端，规则透明）：**

```
score =
    (dup_count 或 1) * 3.0          # 同事件簇热度 → 重要性代理
  + positioning_w                   # 官方 2.0 / 机构 1.5 / 大V 1.0 / 新闻源 0.5 / 快讯源 0.3
  + event_w                         # event_type ∈ {macro, policy, earnings} → 2.0；其它非空 0.5
  + sentiment_w                     # bull/bear → 1.0；neutral/空 → 0
  + min(len(tickers), 4) * 0.5      # 可操作标的
  + item_type_w                     # 分析 1.0 / 聚合 0.8 / 资讯 0.5 / 快讯 0.3
  + recency_w                       # 回溯窗内线性衰减, 最新 +1.0, 窗末 0（「全部」则不加）
```

同分按 `time` 新到旧。`score_parts` 为 `[{label, points}, ...]`，右栏原样展示。现有 `reco.py` 已覆盖 dup / 机构 channel / 重大事件 / 情绪 / 标的五项；落地时把 channel 权重改为（或叠加）`positioning`，并补 `item_type` 与时间衰减。

#### 交互流

1. 进入子页 → `registerSubs` 高亮 `reco` → 拉 sources + stats → 默认全选启用源、`since=24h`、`sort=score` → 请求 `/wb-api/recommend`。
2. 改回溯 / 改勾选源 / 点标签 chip → 重拉推荐列表（不清已勾选的条目，避免误操作丢选择）。
3. 点列表行 → 右栏展示该条 `score_parts`。
4. 勾选若干条 → 点「把勾选加入生成」：写入跨页状态（见第二节）→ `tab='gen'` → `WB.shell.setSub('gen')`。
5. 单行「加入」：同上，只带这一条。
6. 资讯页「加入素材篮」仍写 `WB.basket`；本页打开时，若篮非空，工具条出现「并入素材篮 N 条」次级按钮（不自动跳）。

#### 本期留桩点

- 常用源组的保存/切换（写区本可落 `data/workbench/reco_prefs.json`，UI 先不做）。
- `score_model`（LLM/专用重要性模型）。排序下拉里「重要性(模型)」选项 disabled。
- 不在本页触发 `sources refresh` / `sources fetch`。

### 1.2 内容生成（`gen`）

#### 页面目的

把「内容生成（工作流）」做成一块**实时编辑画布**：信息选择 + 四个生成模块（信息检索 / 快照抓取 / 技术分析 / 聚合分析）+ 模块排列组合 + 固定模板。旁边挂历史记录（只读运行）和草稿（工作台自有写区）。生成按钮本期是桩。

覆盖要素：**实时编辑**、**信息选择**、**信息检索**、**快照抓取**、**技术分析**、**聚合分析**、**排列组合**、**固定模板**、**历史记录**、**草稿**。

实时编辑的等式（冻结自需求原文）：

```
内容生成（工作流）= 实时编辑
                 = 信息选择
                 + 生成模块（信息检索 / 快照抓取 / 技术分析 / 聚合分析）
                 + 排列组合
                 + 固定模板
```

四个模块勾选且排好序 + 选定模板 = 一份可存草稿、可被自动化任务引用的「工作流快照」。正文 textarea 是人工改稿位，与模块输出占位分区，不用卡片套卡片。

#### 布局区块

```
+--------+------------------------------------------------------------------+
| 子菜单  | 顶条: 固定模板 [morning-paper - 早报 v]   草稿状态 未保存/已存 d…   |
|        | 模块排列组合（可上移/下移/开关, 1px 分隔的横条, 非四张卡套卡）        |
|        |  [x] 1 信息检索   [x] 2 快照抓取   [ ] 3 技术分析   [x] 4 聚合分析   |
|        |  [上移] [下移]     [存草稿] [另存] [定稿去发布]  [开始生成]桩         |
|        |------------------------------------------------------------------|
|        | +------------------+------------------------+------------------+ |
|        | | 信息选择          | 实时编辑                | 历史记录 / 草稿  | |
|        | | 已选 N 条         | 标题 input              | [草稿|历史] 切换 | |
|        | | (1px 列表)        | textarea 正文           |                  | |
|        | | 摘要 · 源 · 时间  | 字数 tabular-nums       | 草稿: 标题/时间  | |
|        | | [上移][下移][移除]| ------------------------| 点行=载入编辑器  | |
|        | | [从推荐信息添加]  | 模块输出区（占位/只读）  | [删除草稿]      | |
|        | | [从素材篮并入]    |  信息检索: (相关条目)    |                  | |
|        | |                  |  快照抓取: (桩)          | 历史: flow@date | |
|        | |                  |  技术分析: (桩)          | status badge    | |
|        | |                  |  聚合分析: (桩)          | 点开 steps/产物 | |
|        | +------------------+------------------------+------------------+ |
+--------+------------------------------------------------------------------+
```

- 三栏用 1px 分隔，每栏内部列表也是行，不套 `.card` 进 `.card`。
- 模块条是「排列组合」的唯一操作面：开关改变组合，上移/下移改变顺序。顺序写入草稿 `modules: [{id, on}, ...]`。
- 固定模板下拉绑定真实工作流名（`/wb-api/flows` 的 `name`）。

#### 数据来源

| 用途 | 接口 | 标注 |
|---|---|---|
| 固定模板列表 | `GET /wb-api/flows` | **现有接口**（扫描 `ai-workflow/flows/builtin\|imports/*/workflow.yaml`） |
| 历史记录（运行状态机） | `GET /wb-api/runs` | **现有接口**（`data/runs/<流>/<日期>/run.json`，只读） |
| 历史产物预览 | `GET /wb-api/artifacts` + `GET /wb-api/artifacts/file?path=` | **现有接口**（只读 `generator/output/`） |
| 信息选择：从推荐页带入 / 素材篮 | 跨页状态 `WB.articleCtx` + `WB.basket`（localStorage） | 前端已有篮；ctx **新增通道**（第二节） |
| 信息检索模块的只读补拉 | `GET /wb-api/v1/items?tickers=&q=&since=` | **现有接口**（按已选条目的标的/关键词再查，结果进模块输出区，不自动改正文） |
| 草稿 CRUD | `GET/POST/DELETE /wb-api/drafts`（及可选 `GET /wb-api/drafts/{id}`） | **需新增接口**（`data/workbench/drafts.json`；后端已有 upsert 骨架，按第三节契约对齐） |

四个模块的语义（详细执行用户之后再做，本期只把选择与排列做成真实 UI 状态）：

| 模块 id | 名称 | 本期 | 以后 |
|---|---|---|---|
| `retrieve` | 信息检索 | 可真做：用已选 tickers/标题词打 `/v1/items`，结果列表只读 | 纳入工作流步骤 |
| `snapshot` | 快照抓取 | 按钮桩 | 对 url 做快照/正文提取（subprocess，不手写三板块） |
| `tech` | 技术分析 | 按钮桩 | 按标的出技术面段落 |
| `aggregate` | 聚合分析 | 按钮桩 | 把已选信息聚成综述（对齐现有 morning-paper 类 flow） |

#### 交互流

1. 从推荐信息跳入：读取 `WB.articleCtx.items`，填进信息选择；若带 `draftId` 则先拉草稿再把新条目追加（去重按 item `id`）。
2. 从内容发布「继续编辑」跳入：`draftId` 载入 title/content/items/modules/template，textarea 可改。
3. 改模板、改模块开关/顺序、改正文、改信息选择顺序 → 顶条标「未保存」。
4. 「存草稿」：`POST /wb-api/drafts`（有 id 则更新）。成功后刷新右栏草稿列表与左菜单 cnt。
5. 「定稿去发布」：先静默保存（status 置 `ready`）→ `tab='pub'` + `setSub('pub')` + ctx 带上该草稿 id，发布页自动选中该行并展开下方发布区。
6. 「开始生成」：disabled 桩，旁注 `python cli.py flows run <模板名> --auto`（无模板时写 `<工作流>`）。不调 LLM，不写 `data/runs/`。
7. 点历史记录一行：展开 `steps` / `artifacts`（只读）；不覆盖当前编辑器，除非用户点「载入产物到编辑器」（该按钮本期也可留桩，避免误覆盖）。
8. 点草稿一行：确认未保存变更后载入。删除走 `DELETE /wb-api/drafts/{id}`。

#### 本期留桩点

- 「开始生成」及任何 `flows run`。
- 快照抓取、技术分析、聚合分析的真实执行（信息检索可先接只读 `/v1/items`，失败则显示空态，不挡存草稿）。
- 把草稿文件推入 `auto-publisher/autopub/articles/`（工作台不得写三板块目录；面板注明「推队列下期经 `cli.py`」）。
- 模块拖拽（本期按钮上移/下移即可）。

### 1.3 内容发布（`pub`）

#### 页面目的

上半看**草稿**，点稿件跳回内容生成继续编辑；用户确定某篇后，**下方就是发布区**：定发布时间、发布账号、发布方式，再交给程序发。发布方式目前规划为 **XAI**（xAI/Grok 系 API 通道）与 **Bit**（比特浏览器指纹浏览器 RPA）两种，选择器本期留桩。下半是**发布记录**（账本只读）。

覆盖要素：**草稿**、**发布记录**、**继续编辑跳转**、**发布时间**、**发布账号**、**发布方式（XAI / Bit）**。

#### 布局区块

```
+--------+------------------------------------------------------------------+
| 子菜单  | 段A 草稿（1px 表, 非卡片）                                        |
|        |  标题 | 更新时间 | 状态(草稿/待发) | 模板 | 操作                    |
|        |  ...  |          |                |      | [继续编辑] [选定发布]   |
|        |------------------------------------------------------------------|
|        | 段B 发布区（仅「选定」后展开; 与段A 用一条 1px 分隔, 不套卡）        |
|        |  当前稿: 《标题》  d0903120000                                     |
|        |  发布时间  ( ) 立即   ( ) 定时  [datetime-local]                   |
|        |  发布账号  复选（来自追踪账号清单; 无账号时提示去追踪页添加）        |
|        |            [雪球 @foo] [东财 @bar] ...                             |
|        |  发布方式  ( ) XAI · xAI/Grok API    ( ) Bit · 比特浏览器自动化     |
|        |            （两项均可点选以记住偏好, 确认按钮仍是桩）                |
|        |  [确认发布]桩                                                     |
|        |  提示: 真发必须先 python cli.py publish run --draft                 |
|        |        工作台不写 state.json, 不写 autopub/articles/                |
|        |------------------------------------------------------------------|
|        | 段C 发布记录（账本只读）                                           |
|        |  统计: 成功 N · 失败 N · 待核 N（待核禁止自动重试, 文案写明人工核实） |
|        |  时间 | 平台 | 文章 | 状态 | 链接                                   |
+--------+------------------------------------------------------------------+
```

发布区在草稿列表**下方**（需求：「确定后下方就是发布」），不要做成右侧抽屉。

#### 数据来源

| 用途 | 接口 | 标注 |
|---|---|---|
| 草稿列表 / 点选后的稿面 | `GET /wb-api/drafts` | **需新增接口**（与生成页共用） |
| 继续编辑跳转 | 不打接口；写 `WB.articleCtx` 后切 `gen` | 前端通道 |
| 把发布时间/账号/方式记在草稿上（方便自动化引用） | `POST /wb-api/drafts` 更新 `publish` 字段 | **需新增接口**的字段扩展；只写 `drafts.json` |
| 发布账号候选 | `GET /wb-api/track/accounts` | **现有接口**（`data/workbench/tracked_accounts.json`） |
| 平台名兜底（无追踪账号时仍能勾平台） | 与追踪页同一份 14 平台常量 | 前端已有 |
| 发布记录 | `GET /wb-api/ledger` | **现有接口**（只读 `state.json`：published / failed / uncertain） |
| 待发队列只读对照（可选一列「磁盘队列」） | `GET /wb-api/artifacts` 的 `queue` | **现有接口**（只读 `autopub/articles/`，本页可折叠，避免和草稿两份清单打架） |

#### 交互流

1. 进入子页默认段A。若 ctx 带 `draftId` + `intent=publish`，自动选中该草稿并展开段B。
2. 「继续编辑」：`intent=edit` + `draftId` → `tab='gen'` → `WB.shell.setSub('gen')`。
3. 「选定发布」：展开段B，不跳页。发布时间默认立即；账号默认勾选该草稿上次 `publish.accounts`，否则空。
4. 改时间/账号/方式 → 可点「保存发布偏好」（真实写入该草稿的 `publish` 对象，仍只写 `drafts.json`）。不点则只留在内存，切走丢失。
5. 「确认发布」：disabled 桩。旁注固定命令：

   `python cli.py publish run --draft`

   若已选平台，可在桩文案追加「对应平台用 `--platforms ...`，具体以 `publish targets` 为准」。
6. 段C 只展示。`uncertain` 行用警示色（现有 `--yellow`），文案「已点发布未确认，须到平台后台核实，禁止自动重试」。不提供重试按钮。

#### 本期留桩点

- 「确认发布」以及任何对 `cli.py publish run` 的调用（有无 `--draft` 都不在本期按钮里真跑）。
- 发布方式 XAI / Bit：radio 可点、偏好可随草稿保存，但**不发起 API、不启动比特浏览器**。选项旁短说明「XAI = xAI/Grok API 通道；Bit = 比特浏览器 RPA」。
- 定时到点自动发：只把 `publish.at` 存进草稿/任务；调度器见自动化子页留桩。
- 禁止：写 `state.json`、往 `autopub/articles/` 丢文件、在 UI 提供「强制重发」。

### 1.4 自动化任务（`auto`）

#### 页面目的

把上面这条链（选信息策略不必每次点，工作流模块+模板固定，发布时间/账号/方式固定）收成**定时任务**。

自动化等式（冻结自需求原文）：

```
自动化 = 建立任务 + 建立工作流 + 选择时间 + 内容发布
```

## 二、子页面之间的跳转联动

主页面 hash 保持 `#/article`。子页切换**不改** `app.js` 路由表（避免 `PAGES.find` 精确匹配失败掉回资讯页）。左侧高亮一律 `WB.shell.setSub(id)`，与 `news.js` 的 `srcFilter` 相同。

四子页在**同一个** `WB.pages.article` 组件内，用 `tab` + `v-show`，状态不丢。跨「图文 ↔ 资讯 / 刷新」才需要可序列化通道。

### 2.1 状态通道

| 通道 | 存什么 | 生命周期 |
|---|---|---|
| 组件内存 `tab` / `picked[]` / `draftId` / `modules` / `template` / `editor` | 图文四子页工作态 | 停在 `#/article` 期间 |
| `WB.basket`（已有, `localStorage` `wb_materials`） | 资讯页「加入素材篮」的条目摘要 | 跨主页面、跨刷新 |
| `WB.articleCtx`（**新增**, `sessionStorage` `wb_article_ctx`） | 跳转意图与载荷 | 同标签页、刷新仍在、关标签即无 |

`WB.articleCtx` 形状：

```json
{
  "intent": "edit",
  "tab": "gen",
  "draftId": "d0903120000",
  "itemIds": ["abc", "def"],
  "items": [
    {"id": "abc", "time": "2026-09-03 12:00", "source": "cls",
     "text": "摘要不超过200字", "url": "https://..."}
  ],
  "modules": [{"id": "retrieve", "on": true}, {"id": "snapshot", "on": true},
              {"id": "tech", "on": false}, {"id": "aggregate", "on": true}],
  "template": "morning-paper",
  "ts": 1756880000000
}
```

`intent` 取值：`handoff`（推荐→生成）、`edit`（发布→生成）、`publish`（生成→发布）、`copy-flow`（生成→自动化）。写入后立刻 `setSub`；目标子页 `watch tab` 或 `mounted` 消费一次后把 `intent` 置空，防止来回切子页重复追加条目。

条目去重键 = 数据站 `id`。`WB.basket` 与 `articleCtx.items` 合并时同样按 id。

可选增强（非必须改 `app.js`）：hash 写成 `#/article?sub=gen&draft=d0903120000`。当前壳只认 `/article`，若要深链，需让 `onHash` 先剥 query 再匹配——列入第四节末段，不阻塞骨架。

### 2.2 推荐信息 → 内容生成（选中的信息带入生成）

1. 用户在 reco 勾选条目（或单行加入）。
2. `WB.articleCtx.set({intent:'handoff', tab:'gen', items:[...勾选...]})`。
3. `this.tab = 'gen'`；`WB.shell.setSub('gen')`。
4. gen 的信息选择区：handoff 条目追加到列表头部（已存在的 id 跳过，toast「N 条已在选择中」）。
5. 不自动存草稿。顶条变「未保存」。

从资讯页来：用户先到图文 → 生成子页点「从素材篮并入」，或 reco 工具条「并入素材篮」。不在资讯页直接改 hash 子参。

### 2.3 内容生成 → 内容发布（存草稿 / 定稿）

- **存草稿**：只写 `drafts.json`，停在 gen，左菜单内容生成 cnt 更新。不切页。
- **定稿去发布**：先 POST 草稿（`status: "ready"`）→ ctx `{intent:'publish', tab:'pub', draftId}` → `tab='pub'` → `setSub('pub')`。发布页展开该稿发布区。
- 未保存就点左菜单「内容发布」：不拦截（详细校验之后再做），发布页草稿列表仍是磁盘上的旧版。

### 2.4 内容发布 → 内容生成（点草稿继续编辑）

1. 点草稿行「继续编辑」（或行双击，二选一即可，本期做按钮）。
2. ctx `{intent:'edit', tab:'gen', draftId}`。
3. `tab='gen'`；`WB.shell.setSub('gen')`。
4. gen `GET /wb-api/drafts` 后按 id 载入（或 `GET /wb-api/drafts/{id}`）。信息选择、模块排列、模板、textarea 全部替换为草稿内容。
5. 若 gen 有未保存变更：先 toast 确认「放弃未保存改动？」——这是唯一需要的轻确认，不做复杂 diff。

路由参数设计（深链备用，与 ctx 等价）：

| 参数 | 含义 |
|---|---|
| `sub=gen` | 打开内容生成 |
| `draft=d0903120000` | 载入该草稿 |
| `sub=pub&draft=...` | 打开发布并选中该稿 |

解析优先级：hash query > `WB.articleCtx` > 默认 `reco`。消费后清 ctx 的 intent，保留 draftId 以便存盘。

### 2.5 自动化任务 → 引用固定工作流与发布配置

- **生成 → 自动化**：gen 顶条可放「固定为定时任务」（次级按钮）。ctx `{intent:'copy-flow', tab:'auto', template, modules}`，auto 右侧步骤2 预填；步骤1 名称默认「模板名 + 日期」；步骤4 若当前草稿已有 `publish` 则拷入。用户仍须填时刻并点保存。
- **发布 → 自动化**：发布区「保存为任务」同理，步骤4 预填时间/账号/方式。
- **自动化 → 生成**：任务行「在生成页打开」：ctx 带 template+modules，**不**带 items（定时任务通常没有当场信息）。gen 只恢复工作流画布，信息选择为空，提示「运行时由推荐规则或人工补选；本期 Top N 自动取数留桩」。
- 任务定义只引用模板名与模块数组，不复制 YAML 文件，不改 `ai-workflow/flows/`。

### 2.6 左菜单与返回

任意子页点左侧四项：只改 `tab` + `setSub`，不清编辑器、不清 reco 勾选（`v-show` 保活）。离开图文主页面（hash 变成 `/news` 等）时 `unmounted` → `setSubs([])`，内存态丢弃；篮与 ctx 按上表保留。

## 四、实施顺序建议

原则：先让四子页在壳层里能点、能看只读数据、按钮全是桩；再打开 `data/workbench/` 写区；最后才做任务定义。任何一期都不接真发、不接真跑 flow。

### 第 0 期 — 四子页骨架（约半日）

- 重写 `article.js`：`registerSubs` 四个子菜单 + `tab` + `v-show` 四块空布局（ASCII 对应的 DOM 分区、工具条、空态文案）。
- `unmounted` 清子菜单。图标内联 SVG，禁止 emoji。
- 生成/发布/跑任务按钮全部 `disabled` + `.stub-tip` 写 CLI。
- **理由**：资讯页已验证这套壳；先把导航和留桩红线钉死，避免旧三栏和四子页两套 UI 并存。

### 第 1 期 — 推荐信息只读（先做有数据的页）

- 落地 / 补齐 `GET /wb-api/recommend`（筛选参数 + 近似分 + `score_parts`；60s 缓存）。
- 左栏选的源、回溯窗、标签 chip、列表排序、右栏构成。
- 勾选 → ctx → 切到生成页（生成页此时只要接得住 `items` 列表即可）。
- **理由**：不写盘、只代理数据站，风险最低；价值排序是本需求相对资讯页的增量，应尽早可评。

### 第 2 期 — 内容生成画布 + 草稿写区

- 信息选择（含素材篮并入）、模块开关与上移下移、模板下拉（真 `/flows`）、textarea。

- 信息检索模块可选用 `/v1/items` 只读补拉；另三模块按钮桩。
- **理由**：草稿是发布页和自动化页的上游；写区只碰 `data/workbench/`，与红线相容。没有草稿，发布页的「继续编辑」无处可跳。

### 第 3 期 — 内容发布（账本真、动作桩）

- 草稿表 + 下方发布区（时间 / 账号 / XAI·Bit）。
- 发布偏好写回草稿 `publish` 字段。
- 发布记录接 `/ledger`；uncertain 文案按红线写死。
- 「确认发布」保持桩。
- **理由**：账号复用已有追踪接口，账本只读已有；把「确定后下方就是发布」的版式定住。真发必须继续 `--draft` 先行，不能为了页面完整去调 publish。

### 第 4 期 — 自动化任务定义

- `schedules.json` CRUD、四步表单、从生成/发布复制工作流与发布配置。
- 调度、立即跑、reco Top N、queue/publish 去向全部留桩。
- **理由**：任务是前三页的「固定下来」；先有可保存的模板+模块+时刻+发布偏好，系统计划以后用同一份 JSON 挂即可，不必再改页面结构。
