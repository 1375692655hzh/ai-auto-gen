# 打标模型选型（morning-digest tag 步）

> 2026-08-29 横评定案：**默认 `ark:kimi-k3`**。11 个方舟模型 + grok/gemini 外部参照，
> 同一任务（8-28 早报打标，69 条正文条目）同一提示词对比。

## 结论与用法

```bash
# 默认(推荐): kimi-k3 走方舟订阅额度, 失败自动回落 GLM
py cli.py flows run morning-digest

# 显式指定 / 回退默认 GLM / 换其他方舟模型
py cli.py flows run morning-digest --set tag_model=ark:kimi-k3
py cli.py flows run morning-digest --set tag_model=""
py cli.py flows run morning-digest --set tag_model=ark:doubao-seed-2-0-lite
```

kimi-k3 生产数据（8-28 实跑）：39/69 条标注、16 图卡全部带解读、98 秒（GLM 约 210s）、
10.7k tokens、编号零错位、板块词表与方向枚举零违规、正确跳过宏观总量条。

## 评测口径（换模型时复测这套）

1. **编号对齐**：锚点条抽查（#8/#17/#20/#38/#45），编号错位=直接出局（插行会张冠李戴）——
   minimax-m3/deepseek-flash 表面纪律满分，实为把「今日焦点」区计入了编号
2. **纪律**：表外板块词=0、方向枚举单值、单条≤3板块、「承压/关注」只用于地缘/事件
3. **逆差条测试**：宏观总量数据（无行业指向）必须跳过——GLM/deepseek-pro/豆包全系管不住手
4. **覆盖与一致**：条数 30-55 健康；与现行基准完全一致率作风格参考（低≠错，需抽查明细）
5. **成本**：token 消耗与耗时（豆包系 36-39k vs kimi-k3 10.8k）

## 工程注意（_ark_complete 的坑，已固化在 flows/steps/morning.py）

- Windows 下 Python subprocess 找不到 npm `.cmd` 垫片；`cmd /c` 有 8191 字符命令行上限
  （13k 字打标任务超限）→ 已改为直接调 `node <npm>/node_modules/@volcengine/ark-cli/scripts/run.js`
- `shutil.which("bash")` 会命中 WSL bash（无 arkcli），不能用
- 思考型模型（glm-5.3/minimax/deepseek-flash）默认 32768 token 全烧思考链、content 为空
  → 统一 `--reasoning-effort low`；`--thinking disabled` 仅部分模型支持（glm-5.3 拒绝）
- arkcli 输出尾部拼版本提示，JSON 解析用 `raw_decode` 截断
- 通道任何失败自动回落默认 GLM，不断流程；真实生效看日志 `[ark] <model> tokens=` 行
  （**没有这行 = 走的是降级**，验证切换时务必确认）
