# ai-auto-gen 三大板块架构实施方案

> 由 codex、grok（grok-4.6-build）、gemini（claude-opus-4-6-thinking）三路独立调研规划 + ZCode 汇总裁决产出（2026-08-28）。
> 三方均实际通读现有代码后独立成稿，本文件是去重、裁决、合并后的统一实施方案。

## 0. 三方共识与分歧裁决

**三方完全一致（直接采纳）：**
1. **不推倒重来**：四个引擎（抓取、生成、Python 发布、Node API 发布）保留，新增三个薄层缝合（来源库、工作流引擎、发布门面），渐进迁移每步可回退。
2. **三板块目录**：`sources/`（来源库）、`flows/`（生成工作流）、`publish/`（发布门面）+ 统一 CLI。
3. **来源库要素**：统一条目 schema + 注册表 + 健康检查 + 失效降级 + 磁盘缓存。
4. **工作流双层结构**：声明式可分享层 + Python 表达力层；prompt/模板外置；包 = 自包含目录（导入导出）。
5. **agent 无关接入**：统一 CLI + `--json` + 退出码语义 + AGENTS.md + "状态即文件"；**MCP 第一期不做**（CLI+JSON+文件契约是所有 agent 的最大公约数，留 facade 作演进缝）。
6. **迁移策略**：旧路径留 re-export shim 一个版本期，双轨产物比对验收后删旧。

**唯一重大分歧——工作流定义格式：**

| 方 | 主张 | 理由 |
|---|---|---|
| codex / grok | YAML 编排为主 + Python 步骤库 | 可分享、同事可手改、agent 可直接读写 |
| gemini-opus | Python 类为主 + YAML manifest 元数据 | 零迁移成本、表达力完整（并发/降级逻辑 YAML 写不了） |

**裁决（混合双轨，两家观点本就兼容）：**
- **`workflow.yaml` 编排层是分享与导入的唯一载体**（同事下载的包以 YAML+prompt+模板为主体，天然可审计、无任意代码执行风险）；
- **`flows/steps/` Python 步骤库承担全部复杂逻辑**（并发、降级、数字校验都在步骤内部，YAML 只有 `steps 序列 + with 参数 + when 布尔 + review 标记`，严禁演化成脚本语言）；
- **Python 类整包逃生舱完整保留**（现有 `WorkflowBase` 子类机制不废，YAML 引擎与 Python 类共用同一 engine 与存档/断点/审核语义）。

```
├── adapters-kit/                 # 保留为 Node API 适配器引擎, 子进程调用
├── video/                        # Remotion 引擎一行不改(story.json 契约保持)
├── data/                         # 全部运行时数据(gitignore)

│   ├── cache/sources/            # 来源缓存
│   ├── health/sources-health.json
│   ├── runs/<flow>/<date>/       # 工作流产物 + run.json 状态机
│   ├── queue/                    # 待发目录(= autopub/articles, 配置指向)
│   └── state/publish-state.json  # 发布账本(从 autopub/state.json 迁移)

```

**边界规则**：依赖单向 `cli.py → sources/flows/publish → (autopub|video|adapters-kit)`；三板块只通过文件契约交互（sources 产出 `SourceItem` → flows 消费；flows 产物落 `data/queue/` → publish 消费）；Python 与 Node 只通过子进程 + JSON stdout 交互，禁止跨界嵌框架。

## 2. 板块一：来源库（sources/）

**来源定义 = Python 实现文件 + catalog.yaml 元数据**（代码表达 WAF 破盾这类逻辑，YAML 管人读目录与开关）：

```python
@source(id="futu_morning", kind="peer_article",      # flash|peer_article|calendar|market|announcement|evidence
        auth="none", schedule="weekday~07:30",
        risk="medium", params={"limit_articles": 1})
def fetch(conf: dict) -> list[SourceItem]: ...
```

- **SourceItem**：`{id, kind, time, title?, text, source, url?, media?, raw?}`——兼容现有快讯型（无 title）与文章型，提供 to_legacy 转换保 shim。
- **纯 YAML 加源**（grok 方案采纳）：`http_json` 通用 fetcher 声明 URL/参数/JSONPath，不写代码即可加简单源；复杂源才写 Python。
- **健康检查**：`aag sources check` 逐源实抓，写 `data/health/sources-health.json`（`ok|degraded|dead` + 连续失败数 + 最后成功时间）；`dead`（连续 3 败）在 gather 时自动跳过并列出，修复后 check 复位。
- **缓存**：快讯类 TTL 10 分钟、文章类当日有效；`--fresh` 绕过。保护反爬源与调试重跑。
- **降级链**：catalog 里 `fallbacks: [yuanbao]`，源挂了自动走替代（现有 gangtise→元宝行为显式化）。

## 3. 板块二：生成工具（flows/）——最复杂板块

### 3.1 工作流包结构（分享单元）

```
flows/builtin/morning-paper/        # 或 flows/imports/<name>@<ver>/
├── manifest.json        # {id,title,version,requires_engine,requires:{sources,secrets,python,node},params,steps,outputs}
├── workflow.yaml        # 编排(唯一必需)
├── prompts/*.md         # 本包提示词(frontmatter+模板), 覆盖全局同名
├── templates/           # article/*.j2 | image/*.yaml | video/*.yaml, 覆盖全局同名
├── steps_local.py       # (可选)私有步骤, 导入时显式确认(防任意代码)
└── PACK.md / README.md  # 给同事: 干什么/配什么/怎么改
```

`workflow.yaml` 示例（严格四要素：steps 序列 + with 参数 + when 布尔引用 + review 标记）：

```yaml
id: morning-paper
params: {items: 15, with_video: false}
steps:
  - {id: fetch,  uses: fetch_sources, with: {kinds: [flash, peer_article], health_check: true}}
  - {id: rank,   uses: llm_rank,      with: {prompt: prompts/daily/rank.md, quota: "宏观≥2,海外≥2"}}
  - {id: expand, uses: llm_expand_parallel, with: {workers: 2, degrade: summary_only, verify: numbers}}
  - {id: assemble, uses: assemble_daily, review: true,
     with: {article_template: article/morning-daily.j2, outputs: [md, voice, json]}}
  - {id: video,  uses: render_video, when: "{params.with_video}", with: {story_template: video/morning.yaml}}
```

引擎语义 = 现有 `WorkflowBase`：每步产物存 `data/runs/<flow>/<date>/<step>.json`，已有即跳过（断点续跑），`--from/--only/--fresh` 不变。

### 3.2 导入/导出/分享

- 导出：`aag flows export morning-paper -o 包.zip`（永不包含 secret/state/profiles；含敏感文件扫描）。
- 导入：`aag flows import 包.zip` → manifest 校验（id 冲突提示重命名、requires_engine semver 比对、`steps_local.py` 白名单确认）→ 解包 `flows/imports/` → `flows list` 即见 → `flows lint` 校验引用完整性。
- 同事即用：clone 仓库 → `aag flows run morning-paper`；下载的变体导入即用。

### 3.3 自定义难度梯度（L1→L4，每级有验证路径）

| 级 | 改什么 | 怎么改 |
|---|---|---|
| L1 参数 | 条数/配额/开关 | `data/config.local.yaml` 覆盖或 `--set items=10`（不进 git，不影响分享） |
| L2 模板/提示词 | 文风/版式/配色/标题规则 | 直接编辑包内 prompts/、templates/，`--from assemble` 生效 |
| L3 流程 | 增删步骤/换模板/移审核点 | 编辑 workflow.yaml，`flows lint` 校验 |
| L4 新逻辑 | 新步骤/新素材形态/新来源 | flows/steps/ 注册函数，或 Python 类整包（逃生舱） |

配套 `aag flows new my-flow --from morning-paper`（复制包作改造起点）。

### 3.4 三种素材模板体系（renderer 步骤，任何工作流可插）

- **文章**：jinja2 模板，输出直接落 `data/queue/`（发布链路零改动）。
- **图片**：布局参数外置 YAML（画布/色板/卡片结构/文案槽位），Pillow 渲染代码不外置只外置数据；字体名→路径解析带三平台候选表。
- **视频**：story.json schema 与 10 个 React 模板**完全不动**；模板化的是"内容→场景"映射层（分类→模板、字段→data、footnote 规则），新文章类型配新 map 即可出片。project.json 审核门禁（draft→reviewed→built）保留。

### 3.5 审核点非交互化（agent 驱动关键，codex 方案采纳）

非 TTY 环境（agent/CI）审核点不再 `input()` 阻塞：写 `run.json: {"status":"waiting_review","step":"assemble","artifact":"...md"}` 后退出（退出码 2）；审核 = 直接编辑产物文件，`aag flows resume` 续跑。TTY 下交互行为不变。

## 4. Agent 无关接入层

**统一 CLI**（`python cli.py` / `bin/aag`），全命令 `--json`；退出码：`0 成功 / 2 需人工介入（登录/审核/验证码）/ 3 业务失败 / 4 配置缺失`。

```
aag doctor                        # 环境体检: python/node/ffmpeg/字体/密钥/登录态/来源健康/待发队列
aag sources list|check|fetch <id> [--fresh]
aag flows list|lint|run <name> [--date --auto --from S --set k=v] | status | resume | new | export | import
aag publish login [plat...] | status | run [--file --platforms --draft --yes]
aag skills install [claude|zcode|cursor|all]
```

**约定文件（agent 的共享内存）**：`data/runs/<flow>/<date>/run.json`（状态机+产物清单）｜`data/queue/*.md`（待发）｜`data/state/publish-state.json`（账本，agent 只读）｜`data/health/sources-health.json`｜`data/config.local.yaml`。

**AGENTS.md**（仓库根）：项目一句话 → 三板块地图 → 命令速查（标注副作用/需 --yes 才真发）→ 约定文件表 → 红线（勿手编账本、勿提交 data/ 与 secret、发布先 --draft、勿改 video/src/active-story.ts）→ 常见任务配方。

**skills/**：每个 skill 是标准 SKILL.md（目标→doctor→命令序列→成功判据），`aag skills install` 装到各 agent 技能目录。**MCP 暂不做**，能力先收敛到 sources/flows/publish 三个 Python facade，未来要 MCP 只是薄壳。

## 6. 风险清单与关键取舍

1. **平台适配器持续腐化**（最大长期风险）：选择器随平台改版失效。对策：故障隔离单文件 + draft 校准 + 截图留证为标准修复流程写进 AGENTS.md（agent 读截图可自助改 selector）；doctor 登录态检查让坏尽早暴露。不追求自愈。
2. **YAML DSL 范围失控**：硬边界四要素，更复杂逻辑必须下沉 steps/；Python 逃生舱保证"不够用也无所谓"。
3. **双语言栈**：进程边界 + 文件契约是底线；adapters-kit 结果经 stdout JSON 回传账本。
4. **账本是防重发生命线**：统一账本**继承** state.py 全部安全语义（原子写/uncertain/损坏熔断），旧账本一次性迁移 + 一个版本期双写兼容，防同事机器新旧 CLI 并用漏记。
5. **分享链代码信任**：steps_local.py 导入显式确认 + README 明示只从信任的人导入；长期可加 manifest 签名。
6. **反爬源可用性**：risk 标记 + fallback 链 + 缓存降压 + dead 自动跳过。
7. **同事环境差异**：doctor 逐项体检（字体/ffmpeg/Node/Playwright/密钥），requirements 锁版本，README 分"用户安装/开发"两节。
8. **迁移期双入口**：shim + deprecation warning，双轨产物比对验收后删旧，兼容层保留一个版本期。
9. **明确不做**：Web 化工作流编辑器、自建调度服务（用系统计划任务 + --auto）、adapters-kit 迁 Python、第一期 MCP。
