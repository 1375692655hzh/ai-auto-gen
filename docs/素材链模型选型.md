# 素材链模型选型（morning-paper rank/expand 步）

> 2026-08-30 横评定案：**rank_model / expand_model 默认 `ark:kimi-k3`**。
> 11 个方舟模型，同一任务（8-30 真实快讯池 150 条精排 + 扩写保真）同一提示词对比。

## 结论与用法

```bash
# 默认(推荐): 全链默认 kimi-k3(空 model 即 K3, 见 common.gen_default_model)
py cli.py flows run morning-paper

# 显式指定 / 回默认通道 / 换其他方舟模型
py cli.py flows run morning-paper --set rank_model=ark:kimi-k3
py cli.py flows run morning-paper --set rank_model= --set expand_model=
py cli.py flows run morning-paper --set expand_model=ark:glm-5-3-flash
```

## 任务画像

素材整理链 = morning-paper 流程的 rank（全池 150 条选 15，带配额/类别/排序约束的 JSON 数组）
+ expand（快讯+证据材料 → 结构化 JSON，**数字必须逐字来自材料**，材料稀缺时必须少写不凑）。
对模型的核心要求：**长列表纪律（编号/枚举/配额零违规）、数字零幻觉、3000 token 预算内一次成型、快**。

## 评测口径（换模型复测这套）

1. **rank 可解析**：生产 parse_llm_list（剥围栏+`[...]`+strict json.loads）必须一次过——
   doubao-lite 内嵌引号不转义、minimax 截断无闭合，生产直接 sys.exit
2. **3000 token 预算**：生产 rank max_tokens=3000，思考型模型烧链后 content 为空=出局
   （补测 8000 只为区分"能力差"vs"预算不匹配"，不改生产预算）
3. **锚点命中**：5 条多源重磅必选；**诱惑误选**：7 条名人八卦/文娱/社会新闻不占 15 席
4. **sparse 保真**：仅一条数字密集快讯、无搜索无正文——编数字即露馅；kimi-k3 唯一零幻觉
   且诚实只写 1 段（"材料不足就少写"纪律）
5. **速度**：素材链每天 rank×1 + expand×15，kimi-k3 全链最快（expand 7s/条 vs 豆包系 20-50s）

## 工程注意

- 分发在 `generator/daily.py::_llm`（与 morning._llm_call 同语义：`ark:` 前缀走 arkcli，失败降级默认通道）
- `daily.rank_items/expand_item` 增加了 `model=""` 参数，旧调用零影响
- 与 synth/article/tag/enrich 同用 kimi-k3，全链统一模型便于归因

## 默认模型与回落链(2026-08-30 定案)

`common.gen_llm` 是生成链唯一分发入口(morning._llm_call / daily._llm / tag / enrich / image 全部走它):

```
显式 model 或空(默认 ark:kimi-k3)
  → arkcli 方舟订阅(主通道)
  → 失败: kimi 官方 API(仅当配置了 key: autopub/secret.local.json 的 kimi_api_key 或环境变量 KIMI_API_KEY)
  → 仍失败/未配: 旧默认通道(secret.local.json 的 deepseek-v4-pro, 最终兜底)
```

- 空 model 不再漏进 autopub secret 的 deepseek——默认即 K3
- 全局换默认模型: `data/config.local.yaml` 写 `gen_model: ark:<名>`
- kimi 官方 API 模型名默认 kimi-k3, secret 的 `kimi_api_model` 可覆盖
