# 源与信息分类体系（v5 双标签制，2026-09-03 用户拍板）

> 2026-09-01 起草；2026-09-03 用户拍板双标签制并 MoA（我+grok+codex）三方方案汇总落地。
> 核心原则：**源标签 = "它是谁"（身份，录入时固定）；信息标签 = "它说了什么"（内容，逐条打标）**——两个体系正交，不混用。
> **枚举单一真相 = `sources/taxonomy.py`**（市场/定位/类型/L1→L2 全枚举 + 漂移别名表 + 校验器），tags.py / tagger.py / llm_tag.py / store.py / serve.py 一律从它取，禁止在别处复制维护（此前 L2 漂移 209 种的根因就是枚举三处散养）。

## 〇、总览图（v5）

## 一、源标签（页面卡片徽章，3 个字段）

### 【市场】8 值（多选，主市场在前）

`全球` / `美国` / `A股` / `香港` / `台湾` / `日本` / `韩国` / `土耳其`

- 全部是**地理市场**口径（A股保持"A股"不改名，用户拍板原文如此）
- 一个源覆盖多市场时主市场在前（如 CNBC 晨报 = [美国, 全球]）
- X 两大入口源（twitter_kol_flash/views）放宽到池全景 [全球,美国,台湾,日本,韩国,土耳其]；条目市场按账号各自继承

### 【定位】谁在说（5 值，单值）

| 值 | 定义 | 在册例子 | 源数 |
|---|---|---|---|
| `官方` | 交易所/监管/政府/官媒通讯社 | hkexnews、美联储、央视、中央社、共同社 | 39 |
| `机构` | 数据商/券商研究/平台机构号/自建数据产品 | 东财研报、富途晨报、财经日历、行情摘要 | 17 |
| `大V` | 社交个人/KOL 观点聚合 | 新浪意见领袖、twitter_kol_*、threads_kol_digest | 6 |
| `快讯源` | 滚动快讯栏（媒体快讯流+数据商快讯接口） | 财联社电报、新浪7×24、金十 | 35 |
| `新闻源` | 商业财经媒体（成文报道/汇编） | CNBC、鉅亨网、同行早报聚合 | 13 |

> 定位推导规则（taxonomy.py）：`exchange/media_official→官方`、`broker_research/social_official→机构`、`kol→大V`；`media_finance/data_vendor` 按 kind 切开（flash→快讯源，其余→新闻源/机构）；`aggregator` 五源逐源指定。
> X 池账号定位按 role 派生：`media→新闻源`、`data_bot/breaks→快讯源`、`company→机构`、`analyst/trader/kol/insider→大V`。role 字段保留，仍驱动 flash/views 抓取分流，不受定位影响。
> legacy：旧 channel 八值仍在 meta 里保留一个兼容期，展示/筛选一律用定位。

### 【简介】一句话

- 110 源：tags.py 第五字段 `brief`（title 首分句 ≤40 字）
- 131 X 账号：`note` 字段即简介（人工录入时写的一句话）

## 二、信息标签（每条内容的分拣，4 个字段）

### 【市场】同 8 值，可多挂

继承源/账号市场为底；ticker 词典命中时**并集扩展、不覆盖删除**（grok 裁决：源市场是覆盖声明，ticker 只能证明"还涉及"，不能证明"不涉及"）。外汇对/大宗合约代码不写入市场，只补赛道。

### 【类型】4 值（2026-09-03 拍板：聚合/快讯/资讯/分析）

| 值 | 定义 |
|---|---|
| `聚合` | 每条内容本身是"多信息汇编"：早报/日报/精选/综述/日历/行情摘要（kind=peer_group/extras_group，或源在白名单 AGG_SOURCES） |
| `快讯` | kind=flash 滚动快讯流的单条（未中观点信号） |
| `资讯` | 单篇客观事实：新闻/公告/行情/日历条目/数据 |
| `分析` | 含主观研判的一切：研报/目标价/评级/深度解读/KOL 观点 |

**类型瀑布（纯函数 derive_item_type，自上而下命中即停）**：
1. fetcher 显式给值
2. 聚合锁：kind∈{peer_group, extras_group} 或源在 AGG_SOURCES 白名单 → `聚合`
3. info_type=analysis（观点信号命中）→ `分析`（快讯管道里的观点升级为分析，不当快讯丢弃）
4. kind=flash → `快讯`
5. 其余 → `资讯`

> `info_type` 六值（news/analysis/data/calendar/filing/rumor）**保留为内部细类**，rumor 仍是可信度标记不进类型四值（传言是可信度维，不是体裁维）。LLM 精标纠偏 info_type 后 item_type 自动重算。

**与赛道/情绪的关系（2026-09-02 裁决）**：全类型一视同仁打赛道/情绪/ticker，**无类型豁免**（v2 的"insight 不打赛道"作废——那是把"类型不细分"误读成了"赛道不打标"）。唯一合法的空是内容决定：纯宏观叙事无赛道属性，`sectors=[]` 或挂"宏观与政策"。

- 纯宏观/大盘信息 → sector 挂 `宏观与政策` 或留空，不硬塞（2026-09-02 裁决：分析类照常打赛道，唯一合法的空是内容决定的）

### 【情绪】bull / bear / neutral / null

观点与分析类必填，快讯类可空。沿用 threads 项目已有的情绪维度。

## 三、打标机制（谁给信息打标签）

| 标签 | 机制 |
|---|---|
| 源【市场】【定位】【简介】 | 录入时填死（tags.py 回填表），定位可由 channel×kind 推导（taxonomy.positioning_of），X 账号按 role 派生 |
| 信息【市场】 | 继承源/账号为底 + tagger ticker 命中并集扩展（taxonomy.norm_markets 统一新值域） |
| 信息【类型】 | 纯函数投影 taxonomy.derive_item_type(kind, info_type, source_id)，零 LLM |
| 信息【赛道】【情绪】 | 规则先行（tagger 词典）+ LLM 精标（llm_tag，L1/L2 全枚举注入提示词、L3 开放、写库校验）；**全类型一视同仁** |
| 条目存储 | items 表：`markets` JSON、`item_type` 四值、`positioning` 五值、`sectors` ["半导体>存储记忆体>HBM"]、`info_type` 六值内部细类、`markets_legacy` 改名前留档 |

## 四、拍板决策点（2026-09-03 全部结案）

1. ~~市场 10 值~~ → **8 值**（美股→美国、港股→香港、外汇/大宗退出市场交给赛道）
2. ~~源双轴拆不拆~~ → 渠道+形态合并为**定位 5 值**（官方/机构/大V/快讯源/新闻源），channel 降 legacy
3. ~~信息类型~~ → **类型 4 值**（聚合/快讯/资讯/分析），info_type 六值保留内部细类含 rumor
4. ~~L1 板块 18 个~~ → **19 个**（补通信与卫星，军工国防→军工与航空航天）
5. **L2 封闭 / L3 开放** → 确认可行，加每 L1 预置"其他"收容位 + 写库校验器
6. **情绪字段** → 进体系（观点类必填）
7. **LLM 打标** → refresh 轮末批量精标（llm_tag.py），只纠 info_type news↔analysis + 赛道/情绪/事件
