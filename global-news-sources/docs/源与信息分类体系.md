# 源与信息分类体系（待拍板稿）

> 2026-09-01 起草。解决两件事：①源卡片在同一个页面展示时的区分标签；②每条信息内容的分拣标签。
> 核心原则：**源标签 = "它是谁"（身份，录入时固定）；信息标签 = "它说了什么"（内容，逐条打标）**——两个体系正交，不混用。

## 〇、总览图

```
源(110个, 身份标签, 静态)
 ├─ 【市场】  A股/港股/美股/日本/韩国/台湾/土耳其/全球/外汇/大宗   (10值, 可多个)
 ├─ 【渠道】  谁在生产: 8值                               (单值)
 ├─ 【形态】  给什么: 6值                                 (单值)
 └─ 【风险】  low/medium/high                             (已有)

信息(每条内容, 内容标签, 动态打标)
 ├─ 【市场】  同上10值, 可多个(讲美股的土耳其源=信息挂美股)
 ├─ 【类型】  信息是什么: 10值封闭枚举                     (单值为主)
 ├─ 【赛道板块】 L1一级板块18个(封闭) → L2赛道(封闭) → L3主题热点(开放)  (可多个; insight 分析类不打)
 └─ 【情绪】  bull/bear/neutral                           (可选, 观点类必填)
```

## 一、源标签（页面卡片徽章，4 个字段）

### 【市场】10 值（多选，主市场在前）

`A股` / `港股` / `美股` / `日本` / `韩国` / `台湾` / `土耳其` / `全球` / `外汇` / `大宗`

- 前七个是**地理市场**（沿用源录入规范的七市场裁决）；`外汇`/`大宗` 是**资产类别**（外汇快讯源如 InvestingLive、商品源如 SMM/EIA，不按国别归属）；`全球` 是**跨市场全球宏观**（X 池已实装此值，如 El-Erian 这类全球宏观号）
- 一个源覆盖多市场时主市场在前（如 CNBC 晨报 = [美股, 全球]）

### 【渠道】谁在生产（8 值，单值）

| 值 | 定义 | 在册例子 |
|---|---|---|
| `exchange` | 交易所/监管官方披露 | hkexnews、cls_announcements |
| `media_official` | 官媒/通讯社 | AA、共同社、韩联社、中央社 |
| `media_finance` | 财经媒体 | CNBC、财联社、鉅亨网 |
| `data_vendor` | 数据商/金融终端 | 东财、新浪、金十、finnhub |
| `broker_research` | 券商/投顾研究 | 东财研报、富途晨报 |
| `kol` | 社交平台个人号 | twitter_kol_*（analyst/trader/kol/insider 角色） |
| `social_official` | 社交平台机构/公司号 | twitter_kol_*（media/company 角色） |
| `aggregator` | 自建聚合产物 | threads_kol_digest、peer_mornings |

> 与 X 池 role 的对应：role 是"账号是什么人"，channel 是"源是什么货"——twitter_kol_flash 的 channel 仍是 `kol` 系，role 留在池内作二级区分。

### 【形态】给什么（6 值，单值，由 kind 直接映射）

| kind | 形态 |
|---|---|
| peer_article | `morning` 成篇早报/长文 |
| flash | `flash` 快讯流 |
| announcement | `announce` 公告披露 |
| market | `quote` 行情数据 |
| calendar | `calendar` 日历 |
| （观点情绪流） | `view` 深度观点 |

### 【风险】沿用 low/medium/high 不动

**110 个在册源全部能自动映射**（kind→形态固定映射 + 登记卡补市场/渠道），不需要返工重写。

## 二、信息标签（每条内容的分拣，4 个字段）

### 【市场】同上 10 值，可多挂

信息与源的市场可不一致（土耳其 KOL 讲美联储 = 源挂土耳其 / 信息挂美股+全球）。

### 【类型】8 值封闭枚举（v2 重设计：单维度 + 优先级瀑布保证互斥）

**旧版病根**：快讯/行情快照是"形态"维度，公告/政策是"主体"维度，分析/观点是"深度"维度，传言是"可信度"维度——四维混在一格里必然重叠（一条公告快讯同时是 flash 又是 corp_event）。v2 只保留一个维度：**这条信息的断言是什么**。

| 值 | 定义（互斥靠下面的瀑布裁决） | 典型内容 |
|---|---|---|
| `filing` 公告披露 | 官方一手：交易所/公司/监管直接发布 | KAP 披露、港交所公告、财报原文 |
| `news` 事实资讯 | 媒体报道的已发生事实（非官方发布） | 订单传闻落地报道、高管变动报道、产品发布 |
| `data` 数据信号 | 可量化的市场数据与机器信号 | 指数收盘、资金流、大宗交易、国会交易异动 |
| `rating` 评级动作 | 投行/机构的评级、目标价、盈利预测调整 | 大摩上调目标价、降级报告 |
| `insight` 深度解读 | 有逻辑链条的分析推演（含研报观点、财报拆解） | 毛利率拆解、降息路径推演、供需分析 |
| `stance` 观点立场 | 无逻辑链的多空表态/情绪/操作建议 | "黄金坑"、"看多载板"、盘感分享 |
| `rumor` 传言爆料 | 未经证实的信息（无论讲什么） | 线人爆料、社群传闻 |
| `calendar` 事件预告 | 未来确定时点的事件 | 除息日、FOMC 日程、IPO 申购 |

**互斥裁决瀑布（从上往下，命中即停）**：
1. 未经证实 → `rumor`（可信度优先，无论主体）
2. 讲未来时点事件 → `calendar`
3. 官方直接发布 → `filing`
4. 评级/目标价调整 → `rating`（优先于 news——"大摩上调目标价"归 rating 不归 news）
5. 纯量化数据 → `data`
6. 媒体转述的已发生事实 → `news`
7. 有逻辑链 → `insight`；无逻辑链纯表态 → `stance`

**自测**（每条只进一格）：
- 台积电发财报超预期 → filing；媒体报台积电拿苹果大单 → news；大摩上调台积电目标价 → rating；群友传台积电要涨价 → rumor；深度拆解台积电毛利率 → insight；"台积电1000是黄金坑！" → stance；台指收盘数据 → data；9/15 除息预告 → calendar ✅

**与源标签的关系**：源的【形态】管"长什么样"（快讯流/早报/公告区），信息的【类型】管"说的是什么"——源形态不再混入信息类型（旧版 flash/quote 两个值就是从形态轴误搬过来的）。

**L3 主题热点（开放标签）**：机器人灵巧手、低空经济、稳定币、核聚变这类"当下热点"由 LLM 自由产出短标签，定期（每月）人工把沉淀多的热点上收为 L2 枚举。**开放层防止体系过时**。

**两类信息不打赛道标签**（2026-09-01 用户裁决）：
- **`insight` 深度解读类**——分析文多跨板块或纯宏观推演，强行归类噪声大；此类内容按作者质量取用，不走赛道过滤
- 纯宏观/大盘信息 → sector 挂 `宏观与政策` 或留空，不硬塞

### 【情绪】bull / bear / neutral / null

观点与分析类必填，快讯类可空。沿用 threads 项目已有的情绪维度。

## 三、打标机制（谁给信息打标签）

| 标签 | 机制 |
|---|---|
| 源四标签 | 录入时填死（登记卡扩展字段），110 存量源写脚本按 kind+登记卡批量补齐 |
| 信息【市场】【类型】 | 规则先行：源级默认值（announcement→corp_event，market→quote）+ 内容关键词修正；拿不准落 LLM |
| 信息【赛道板块】【情绪】 | LLM 打标（digest/synth 环节顺手产出），L1/L2 用枚举约束输出，L3 开放；**insight 类跳过赛道打标**（用户裁决） |
| 条目存储 | dict 扩展：`{"markets": [...], "info_type": "...", "sectors": ["半导体>存储记忆体"], "sentiment": "bull"}` |

## 四、拍板决策点

1. **市场 10 值**——A股/港股/美股/日本/韩国/台湾/土耳其/全球/外汇/大宗，冻结还是预留扩展槽？
2. **源双轴拆不拆**——渠道（谁）+形态（给什么）分开两轴（推荐），还是合并成单轴？
3. **信息类型 8 值（v2）**——断言维度单轴 + 瀑布裁决保互斥，增减哪些？（rumor 走可信度优先通道，rating 优先于 news，这两个裁决规则是否认可）
4. **L1 板块 18 个**——数量合不合适？（申万 31 太细偏 A股，GICS 11 太粗偏美股，18 是折中）
5. **L2 封闭 / L3 开放**这个结构行不行？
6. **情绪字段**要不要进体系？
7. **LLM 打标**走哪个环节挂（digest 时打 / synth 时打）？
