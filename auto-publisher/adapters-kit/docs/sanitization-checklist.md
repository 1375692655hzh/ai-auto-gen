# 脱敏说明与交付清单

## 已移除

- 原工程的上游内容源应用、表格和文档接入。
- 用户登录、权限、数据库、任务队列、业务路由和前端页面。
- 生产账号、Cookie、storageState、手机号、邮箱、账号昵称。
- 固定第三方识别 key、代理地址、代理用户名和密码。
- 部署地址、内部服务地址、品牌素材、业务数据和真实文章。
- 原工程日志落盘实现，替换为不记录查询参数和凭证的最小日志。

## 保留原因

平台公开域名、接口路径、表单字段、DOM 选择器、状态码映射和验证码算法常量属于理解发文实现所必需的工程逻辑。第三方识别服务的公开 API 地址保留为默认端点，但 key、代理和开发者凭证均为空，只允许环境变量注入。

## 自动检查

运行 `npm run check:sanitized` 会扫描：带用户名密码的 URL、疑似手机号、疑似邮箱、固定敏感配置和 Cookie/Authorization 赋值样例。自动规则只能降低误交付风险，不能代替人工复核。

## 对外发送前人工复核

1. 确认目录内没有 `.env`、storageState、浏览器 profile、数据库、日志、截图或抓包文件。
2. 解压最终压缩包，在一个全新目录执行 `npm run check`。
3. 搜索接收方不应知道的公司名、项目名、域名、手机号、邮箱、IP、账号昵称和真实文章标题。
4. 确认示例路径、文章和账号均为虚构值。
5. 与接收方明确：只能使用其自有测试账号；真实发布会产生外部内容；平台条款和接口随时可能变化。
6. 单独通过安全渠道传递接收方自己的测试配置，绝不把凭证重新塞回代码包。

## 当前自动检查结论

以生成脚本运行后的 `npm run check:sanitized` 输出为准。压缩包生成后仍建议再次解压复核，因为压缩动作之外新增的文件不会被本说明自动覆盖。
